# 큐 마이그레이션 및 제거 체크리스트

## 🚀 마이그레이션 준비

### 1. 새 버전 큐 준비
- [ ] 새 큐 설정 검증 완료
- [ ] 새 Consumer 배포 및 테스트 완료
- [ ] 모니터링 설정 완료

### 2. 트래픽 분할 준비
- [ ] Producer에서 큐 선택 로직 구현
- [ ] 환경변수/설정으로 비율 조정 가능
- [ ] 롤백 계획 수립

## 📊 점진적 트래픽 이동

### 1단계: 소량 트래픽 (10%)
- [ ] 새 큐로 10% 트래픽 이동
- [ ] 에러율 모니터링 (< 0.1%)
- [ ] 응답 시간 모니터링 (기존 대비 +10% 이내)
- [ ] 24시간 안정성 확인

### 2단계: 중간 트래픽 (50%)
- [ ] 새 큐로 50% 트래픽 이동
- [ ] 성능 지표 모니터링
- [ ] 큐 백로그 상태 확인
- [ ] 48시간 안정성 확인

### 3단계: 전체 트래픽 (100%)
- [ ] 새 큐로 100% 트래픽 이동
- [ ] 구 큐 신규 메시지 유입 차단 확인
- [ ] 7일간 안정성 확인

## 🗑️ 구 버전 제거

### 사전 확인
- [ ] 구 큐 Ready 메시지: 0개
- [ ] 구 큐 Unacked 메시지: 0개
- [ ] 구 Consumer 모든 인스턴스 중단
- [ ] 구 Producer 완전 중단 확인

### 제거 실행
- [ ] Management UI에서 큐 삭제
- [ ] 또는 CLI 명령어 실행: `rabbitmqctl delete_queue {old-queue-name}`
- [ ] 삭제 확인: 큐 목록에서 제거됨

### 사후 정리
- [ ] 구 버전 Consumer 코드 제거
- [ ] 구 버전 관련 설정 파일 제거
- [ ] 모니터링 대시보드 업데이트
- [ ] 문서 업데이트

## ⚠️ 주의사항

### 절대 하지 말 것
- [ ] RabbitMQ 서버 재시작으로 큐 제거 ❌
- [ ] 메시지가 남아있는 상태에서 큐 삭제 ❌
- [ ] 백업 없이 프로덕션 큐 삭제 ❌

### 롤백 준비
- [ ] 구 버전 Consumer 코드 보관
- [ ] 구 버전 설정 백업
- [ ] 롤백 절차서 준비
- [ ] 긴급 연락망 준비

## 📈 모니터링 지표

### 트래픽 이동 중 모니터링
- **에러율**: < 0.1%
- **응답 시간**: 기존 대비 +10% 이내
- **큐 백로그**: 급격한 증가 없음
- **메모리/CPU**: 정상 범위 내

### 제거 후 모니터링
- **새 큐 성능**: 안정적 처리
- **전체 시스템**: 정상 동작
- **사용자 경험**: 문제 없음

---

**중요**: 프로덕션 환경에서는 반드시 단계적으로 진행하고, 각 단계마다 충분한 모니터링을 통해 안정성을 확인한 후 다음 단계로 진행하세요.
