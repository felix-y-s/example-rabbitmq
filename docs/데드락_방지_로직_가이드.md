# 🔒 데드락 방지 로직 구현 가이드

## 📝 개요

데드락(Deadlock)은 두 개 이상의 트랜잭션이 서로 다른 리소스를 잠그고 상대방의 리소스를 기다리는 상황입니다. 본 문서는 PostgreSQL과 Prisma 환경에서 데드락을 방지하는 다양한 전략과 구현 방법을 다룹니다.

## 🚨 데드락 발생 시나리오

### 전형적인 데드락 상황
```typescript
// Transaction A: product_id=1 → product_id=2 순서로 잠금
// Transaction B: product_id=2 → product_id=1 순서로 잠금
// → 서로 기다리며 무한 대기 (데드락!)
```

### 실제 예시
```sql
-- Transaction A
BEGIN;
SELECT * FROM products WHERE id = 1 FOR UPDATE;  -- 1번 상품 잠금
-- (다른 작업 수행)
SELECT * FROM products WHERE id = 2 FOR UPDATE;  -- 2번 상품 잠금 대기

-- Transaction B (동시 실행)
BEGIN;
SELECT * FROM products WHERE id = 2 FOR UPDATE;  -- 2번 상품 잠금
-- (다른 작업 수행)
SELECT * FROM products WHERE id = 1 FOR UPDATE;  -- 1번 상품 잠금 대기 → 데드락!
```

## 🛠️ 데드락 방지 전략

### 1. 리소스 순서 정렬 (Resource Ordering) ⭐ **추천**

가장 효과적인 방법으로, **항상 동일한 순서로 리소스를 잠그는 것**입니다.

```typescript
// 여러 상품의 재고를 동시에 처리할 때
async reduceMultipleStockWithLock(
  items: Array<{ productId: number; quantity: number }>
) {
  return await this.prismaService.$transaction(async (prisma) => {
    // 🎯 데드락 방지: productId 순서로 정렬
    const sortedItems = items.sort((a, b) => a.productId - b.productId);

    // 정렬된 순서대로 잠금 획득
    const products = await prisma.$queryRaw<Array<{
      id: number; stock: number; version: number;
    }>>(Prisma.sql`
      SELECT id, stock, version
      FROM products
      WHERE id IN (${Prisma.join(sortedItems.map(item => item.productId))})
      ORDER BY id  -- 중요: ID 순서로 정렬하여 잠금
      FOR UPDATE
    `);

    // 재고 업데이트 로직
    const results = [];
    for (const item of sortedItems) {
      const product = products.find(p => p.id === item.productId);

      if (!product) {
        results.push({
          productId: item.productId,
          success: false,
          message: '상품을 찾을 수 없습니다.'
        });
        continue;
      }

      if (product.stock < item.quantity) {
        results.push({
          productId: item.productId,
          success: false,
          message: `재고 부족 (현재: ${product.stock}, 요청: ${item.quantity})`
        });
        continue;
      }

      // 재고 업데이트
      const updatedProduct = await prisma.product.update({
        where: { id: item.productId },
        data: {
          stock: product.stock - item.quantity,
          version: { increment: 1 }
        }
      });

      results.push({
        productId: item.productId,
        success: true,
        message: '재고 감소 완료',
        finalStock: updatedProduct.stock
      });
    }

    return results;
  });
}
```

### 2. 타임아웃 설정

트랜잭션에 타임아웃을 설정하여 무한 대기를 방지합니다.

```typescript
async reduceStockWithLockTimeout(
  productId: number,
  quantity: number,
  timeoutMs: number = 5000
) {
  return await this.prismaService.$transaction(
    async (prisma) => {
      // FOR UPDATE 쿼리
      const products = await prisma.$queryRaw<Array<{
        id: number; stock: number; version: number;
      }>>(Prisma.sql`
        SELECT id, stock, version
        FROM products
        WHERE id = ${productId}
        FOR UPDATE
      `);

      if (products.length === 0) {
        return { success: false, message: '상품을 찾을 수 없습니다.' };
      }

      const product = products[0];
      if (product.stock < quantity) {
        return {
          success: false,
          message: `재고 부족 (현재: ${product.stock}, 요청: ${quantity})`
        };
      }

      const updatedProduct = await prisma.product.update({
        where: { id: productId },
        data: {
          stock: product.stock - quantity,
          version: { increment: 1 }
        }
      });

      return {
        success: true,
        message: '재고 감소 완료 (비관적 락)',
        finalStock: updatedProduct.stock
      };
    },
    {
      timeout: timeoutMs, // 🎯 타임아웃 설정으로 데드락 회피
      isolationLevel: 'ReadCommitted'
    }
  );
}
```

### 3. 데드락 감지 및 재시도

데드락 발생을 감지하고 자동으로 재시도하는 로직입니다.

```typescript
async reduceStockWithDeadlockHandling(
  productId: number,
  quantity: number,
  maxRetries: number = 3
) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await this.prismaService.$transaction(async (prisma) => {
        const products = await prisma.$queryRaw<Array<{
          id: number; stock: number; version: number;
        }>>(Prisma.sql`
          SELECT id, stock, version
          FROM products
          WHERE id = ${productId}
          FOR UPDATE
        `);

        // 재고 처리 로직...
        if (products.length === 0) {
          return { success: false, message: '상품을 찾을 수 없습니다.' };
        }

        const product = products[0];
        if (product.stock < quantity) {
          return {
            success: false,
            message: `재고 부족 (현재: ${product.stock}, 요청: ${quantity})`
          };
        }

        const updatedProduct = await prisma.product.update({
          where: { id: productId },
          data: {
            stock: product.stock - quantity,
            version: { increment: 1 }
          }
        });

        return {
          success: true,
          message: '재고 감소 완료 (비관적 락)',
          finalStock: updatedProduct.stock
        };
      }, {
        timeout: 5000 // 5초 타임아웃
      });

    } catch (error) {
      // 🎯 데드락 에러 감지
      if (this.isDeadlockError(error)) {
        this.logger.warn(
          `데드락 감지 - 재시도 ${attempt}/${maxRetries} (productId: ${productId})`
        );

        if (attempt < maxRetries) {
          // 랜덤 백오프로 재시도
          await this.sleep(Math.random() * 100 + 50);
          continue;
        }
      }

      throw error;
    }
  }
}

/**
 * 데드락 에러인지 확인하는 헬퍼 메서드
 */
private isDeadlockError(error: any): boolean {
  // Prisma/PostgreSQL 데드락 에러 코드 감지
  return error.code === 'P2034' || // Prisma timeout
         error.code === '40P01' || // PostgreSQL deadlock_detected
         error.message?.includes('deadlock') ||
         error.message?.includes('timeout');
}

/**
 * 비동기 sleep 함수
 */
private async sleep(ms: number): Promise<void> {
  return new Promise(resolve => setTimeout(resolve, ms));
}
```

### 4. NOWAIT를 사용한 즉시 실패 처리

잠금을 기다리지 않고 즉시 실패하도록 하는 방식입니다.

```typescript
async reduceStockWithNowait(productId: number, quantity: number) {
  return await this.prismaService.$transaction(async (prisma) => {
    try {
      // 🎯 NOWAIT: 즉시 잠금 실패 시 에러 발생 (대기하지 않음)
      const products = await prisma.$queryRaw<Array<{
        id: number; stock: number; version: number;
      }>>(Prisma.sql`
        SELECT id, stock, version
        FROM products
        WHERE id = ${productId}
        FOR UPDATE NOWAIT  -- 대기 없이 즉시 실패
      `);

      if (products.length === 0) {
        return { success: false, message: '상품을 찾을 수 없습니다.' };
      }

      const product = products[0];
      if (product.stock < quantity) {
        return {
          success: false,
          message: `재고 부족 (현재: ${product.stock}, 요청: ${quantity})`
        };
      }

      const updatedProduct = await prisma.product.update({
        where: { id: productId },
        data: {
          stock: product.stock - quantity,
          version: { increment: 1 }
        }
      });

      return {
        success: true,
        message: '재고 감소 완료 (비관적 락)',
        finalStock: updatedProduct.stock
      };

    } catch (error) {
      if (error.code === '55P03') { // PostgreSQL lock_not_available
        return {
          success: false,
          message: '다른 트랜잭션이 처리 중입니다. 잠시 후 다시 시도해주세요.'
        };
      }
      throw error;
    }
  });
}
```

## 🏆 종합 권장 구현

현재 코드에 적용할 수 있는 개선된 버전입니다.

```typescript
async reduceStockWithLock(
  productId: number,
  quantity: number,
  options: {
    timeout?: number;
    useNowait?: boolean;
    maxRetries?: number;
  } = {}
) {
  const {
    timeout = 5000,
    useNowait = false,
    maxRetries = 3
  } = options;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await this.prismaService.$transaction(
        async (prisma) => {
          const lockClause = useNowait ? 'FOR UPDATE NOWAIT' : 'FOR UPDATE';

          const products = await prisma.$queryRaw<Array<{
            id: number; stock: number; version: number;
          }>>(Prisma.sql`
            SELECT id, stock, version
            FROM products
            WHERE id = ${productId}
            ${Prisma.raw(lockClause)}
          `);

          if (products.length === 0) {
            return { success: false, message: '상품을 찾을 수 없습니다.' };
          }

          const product = products[0];
          if (product.stock < quantity) {
            return {
              success: false,
              message: `재고 부족 (현재: ${product.stock}, 요청: ${quantity})`
            };
          }

          const updatedProduct = await prisma.product.update({
            where: { id: productId },
            data: {
              stock: product.stock - quantity,
              version: { increment: 1 }
            }
          });

          return {
            success: true,
            message: '재고 감소 완료 (비관적 락)',
            finalStock: updatedProduct.stock
          };
        },
        {
          timeout, // 타임아웃 설정
          isolationLevel: 'ReadCommitted'
        }
      );
    } catch (error) {
      // 데드락 또는 타임아웃 감지
      if (this.isDeadlockError(error) && attempt < maxRetries) {
        this.logger.warn(
          `데드락/타임아웃 감지 - 재시도 ${attempt}/${maxRetries} (productId: ${productId})`
        );

        // 지수 백오프 + 지터
        const baseDelay = Math.pow(2, attempt - 1) * 100; // 100ms, 200ms, 400ms
        const jitter = Math.random() * 50; // 0-50ms 랜덤
        await this.sleep(baseDelay + jitter);
        continue;
      }

      // NOWAIT 락 실패는 재시도하지 않음
      if (error.code === '55P03') {
        return {
          success: false,
          message: '다른 트랜잭션이 처리 중입니다. 잠시 후 다시 시도해주세요.'
        };
      }

      throw error;
    }
  }

  // 최대 재시도 횟수 초과
  return {
    success: false,
    message: `재고 감소 실패 - 최대 재시도 횟수 초과 (${maxRetries}회)`
  };
}
```

## 📊 PostgreSQL 에러 코드 참조

### 주요 데드락 관련 에러 코드

| 에러 코드 | 설명 | 대응 방안 |
|-----------|------|-----------|
| `40P01` | `deadlock_detected` | 재시도 |
| `55P03` | `lock_not_available` (NOWAIT) | 즉시 실패 처리 |
| `P2034` | Prisma transaction timeout | 재시도 |
| `25P02` | `in_failed_sql_transaction` | 트랜잭션 롤백 후 재시도 |

## 🎯 핵심 권장사항

### 1. 우선순위별 적용 방법

1. **Phase 1 (즉시 적용)**: 타임아웃 설정
2. **Phase 2 (1주 내)**: 데드락 감지 및 재시도 로직
3. **Phase 3 (필요시)**: 리소스 정렬 또는 NOWAIT 전략

### 2. 모니터링 지표

```typescript
// 메트릭 수집을 위한 로깅
this.logger.log(`데드락 재시도 통계 - 성공률: ${successRate}%, 평균 재시도: ${avgRetries}`);
```

### 3. 성능 고려사항

- **타임아웃**: 너무 짧으면 불필요한 실패, 너무 길면 사용자 경험 저하
- **재시도 횟수**: 일반적으로 3-5회가 적당
- **백오프 전략**: 지수 백오프 + 지터로 경합 상황 완화
