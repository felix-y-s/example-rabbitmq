# 🏗️ 이커머스 주문 처리 시스템 아키텍처

## 시스템 플로우
```text
  [주문 생성] → [재고 확인] → [결제 처리] → [배송 준비] → [주문 완료]
       ↓           ↓           ↓           ↓
   Order Queue  Stock Queue  Payment Q   Shipping Q
```
## 핵심 서비스 구조

  [V]**1. Order Service (주문 관리)**
  - 주문 생성 및 상태 관리
  - 주문 유효성 검증
  - 고객 정보 처리

  **2. Inventory Service (재고 관리)**
  - 재고 확인 및 예약
  - 재고 부족 시 대기열 처리
  - 재고 복구 로직

  **3. Payment Service (결제 처리)**
  - 결제 검증 및 처리
  - 결제 실패 시 롤백
  - 결제 상태 추적

  **4. Shipping Service (배송 관리)**
  - 배송지 검증
  - 배송 업체 연동
  - 배송 상태 업데이트

## 메시지 큐 패턴

  **큐 구조:**
  - order.created → 새 주문 알림
  - inventory.check → 재고 확인 요청
  - payment.process → 결제 처리 요청
  - shipping.prepare → 배송 준비 요청
  - order.completed → 주문 완료 알림

  **Exchange 전략:**
  - Direct Exchange: 정확한 라우팅 (재고, 결제)
  - Topic Exchange: 상태별 알림 (주문 상태 변경)
  - Fanout Exchange: 전체 알림 (주문 완료)
